# teavel-submarine (부력 잠수함)

과학 **'부력'** 단원용 교실 게임. 잠수함을 **버튼 하나**로 조종해 바닷속 장애물을 피하며 끝까지 가는 벨트스크롤 게임이다.
같은 교내망에 붙은 학생들이 **QR로 접속**해 **같은 코스**를 누가 더 높은 점수로 돌파하는지 겨룬다.
교사 PC에서 **exe 한 개를 더블클릭**하면 끝. 학생은 **앱 설치 없이 브라우저**로 들어온다.

📖 **선생님용 사용법은 [사용 설명서(MANUAL.md)](MANUAL.md)** 를 보세요. 이 README 는 만드는 사람을 위한 설명입니다.

구조는 형제 프로젝트 vector-soccer·classroom-quiz 와 같다(LAN 바인딩 · QR · 액터 모델 허브 · 결과 파일 저장 · 교사 화면 localhost 전용).

## 게임 방식

- **누르고 있으면** 고압 공기통의 공기가 앞뒤 밸러스트 탱크로 들어가 물을 아래 구멍으로 밀어낸다 → 밀어낸 물의 부피만큼 부력이 커져 뜬다.
- **떼면** 탱크 위 벤트가 열려 공기가 빠지고 **수압**으로 물이 들어온다 → 부력이 작아져 가라앉는다.
  깊을수록 물이 빨리 들어온다(수심 30m마다 수면의 1배씩 더).
- 잠수함 질량(중력)은 일정하고 부력이 공기탱크 부피에 따라 바뀐다(밸러스트 탱크는 아래가 바다로 열려 있어 그 속 물은 잠수함 질량이 아님).
  탱크 공기 50% = 중성 부력. 알짜힘 = 부력 − 중력 → 가속, 물의 저항이 속도에 비례해 붙는다.
- 잠수함은 **단면**으로 그린다: 탱크 속 수위, 공기관 흐름, 벤트 열림/닫힘, 물 구멍으로 나가고 들어오는 물, 벤트 거품.
  화면 옆(세로 화면이면 아래) 패널에 **탱크 확대 단면 · 부력/중력 화살표 · 수심/수압**, 그리고 큰 버튼.
- 전진은 10 m/s 일정. 장애물: 해저 바위, 수면 빙산, 기뢰(사슬). 진주는 보너스.
- 선체 3칸. 부딪히면 1칸 깎이고 1.5초 무적. 다 깎이면 침몰.
- 점수 = 간 거리(m) + 진주 × 30 + (완주 시) 300 + 남은 선체 × 100.
- 다른 학생 잠수함이 가까이 있으면 반투명 "유령"으로 보인다(5Hz).

## 교사 화면 (`/host`, 교사 PC에서만 열림)

- **진행** 탭: 접속 QR(크게 띄우기 + 접속자 명단) · 코스 카드(새 코스 만들기 · **기록 시작/마감** · 도전 횟수) ·
  코스 지도(장애물 + 달리는 학생 점 실시간) · 지금 주행 중 · 순위표(크게 보기 = 프로젝터용) · 접속한 학생.
- **코스 올리기/내리기**: 내려 두면 학생에게 코스를 보내지 않는다("코스 준비 중", 연습도 불가). 내리면 기록도 닫고 달리던 주행은 무효.
  서버를 다시 켜면 지난 코스를 **내려 둔 채** 복원한다(켜자마자 학생이 달리지 않게). 새로 만든 코스는 바로 올라간다.
- 새 코스는 **연습만 가능** 상태로 열린다(기록 안 됨). **기록 시작**을 누르면 공식 도전만 가능(연습 불가).
  학생별 **최고 점수**가 순위. 도전 횟수는 출발할 때 센다(그만둬도 1회).
- **기록** 탭: 날짜별 코스 목록 · 코스별 순위표 · CSV(최고 기록 / 모든 주행) · 삭제(진행 중인 코스 제외).

코스 하나 = 파일 하나: exe 옆 `results/<날짜>/<시각>-<코스id>.json`
(코스 설정·시드, 학생별 도전 횟수, 공식 주행 기록). 서버를 다시 켜면 **가장 최근 코스를 이어서** 한다(내려 둔 채, 기록 닫힘).

## 빌드 / 실행

```bash
./build.sh                          # dist/teavel-submarine.exe (콘솔 창 = 실행 중 표시, 닫으면 종료)
./build.sh dist/teavel-submarine.exe gui   # 콘솔 없이(-H windowsgui)
go test ./...                       # 물리 JS/Go 일치 · 코스 통과 가능성 · 주행 흐름 테스트
SUB_NO_BROWSER=1 go run .           # 개발 실행(브라우저 자동 열기 끔)
```

기본 포트 **8091**(classroom-quiz 8080, vector-soccer 8090 과 동시에 켜도 겹치지 않게), 사용 중이면 다음 포트로 넘어간다.

## 설계 메모

- **물리는 학생 화면이 돌리고, 서버가 검산한다.** 버튼 반응에 네트워크 지연이 끼면 안 되므로 학생 브라우저가
  60Hz 고정 틱으로 `assets/sim.js` 를 돌린다. 끝나면 **버튼 상태가 바뀐 틱 번호 목록**만 보내고,
  서버가 `sim.go` 로 같은 코스·같은 입력을 다시 계산해 **서버가 낸 점수만** 기록한다. 실제 흐른 시간보다 빨리 끝난 주행은 거부.
- 두 물리 구현은 **비트 단위로 같아야** 한다: 사칙연산·비교·floor·min/max 만 쓰고(초월함수 금지),
  Go 쪽은 물리 값을 `var` 로(상수식은 무한 정밀도로 접혀 JS 와 반올림이 달라짐), 곱을 더하는 식은 `float64(...)` 로 감싸
  FMA 융합을 막는다. `sim_test.go` 가 node 로 sim.js 를 돌려 Go 결과와 비교한다(node 없으면 건너뜀).
  **물리를 바꾸면 두 파일을 같이 바꾸고 `go test`.**
- 코스는 서버가 시드로 만들고(`course.go`) 완성된 장애물 목록을 학생에게 보낸다(JS 는 생성하지 않는다).
  먼저 "지나갈 수 있는 길"(경유점)을 정하고 그 길만 비운 장애물을 세운다. `course_test.go` 의 자동 조종사(빔 탐색)가
  모든 난이도에서 **무사고 완주 경로가 있는지** 확인한다.
- 모든 상태 변경은 `Hub.run()` 단일 고루틴 안에서만 일어난다(락 없음). 서버 틱 10Hz(유령 5Hz, 교사 화면 5Hz).
- 학생 식별: `sessionStorage` 토큰 — 새로고침하면 같은 학생. 브라우저를 닫았다 와도 같은 학번·이름이면 그 학생으로 복귀.
  주행 중 와이파이가 끊겨도 화면의 주행은 계속되고, 끝난 기록은 다시 연결되면 보낸다.

## 아이콘

`branding/` — teaveloper 공용 규격(1024 캔버스 · 800 라운드 사각형 rx 184 · 공식 그라데이션 · 흰 죽방). vector-soccer 와 같은 틀.
간단한 흰 잠수함 한 척(잠망경 포함), 선체 가운데 죽방 엠블럼(배경색으로 파냄). 그림이 단순해 작은 크기(16·32·48px)도 같은 그림을 쓴다.

```bash
cd branding && python gen.py         # icon.svg / icon-small.svg 다시 만들기
node render.js                       # PNG(1024·512·256) + app.ico(256·128·64·48·32·16) — 헤드리스 크롬 사용
cd .. && rsrc -ico branding/app.ico -arch amd64 -o rsrc_windows_amd64.syso   # exe 아이콘(윈도우 빌드 시 자동 링크)
cp branding/icon-small.svg assets/favicon.svg && cp branding/icon.svg assets/icon.svg   # 파비콘 · 입장 화면 로고
```

`rsrc` 는 `go install github.com/akavel/rsrc@latest`. magick 이 있으면 vector-soccer README 의 명령으로 대신 만들어도 된다.
